# 测试与验收

## 1. 后端

正式测试前建议先完成运行依赖预检：

```cmd
cd backend
call .venv\Scripts\activate.bat
python scripts\check_settings.py
python scripts\check_ollama.py
python scripts\check_database.py
python scripts\check_business_schema.py
```

然后执行完整测试：

```cmd
python -m pytest -q
```

测试目录：

- `tests/unit/`：核心服务、配置、Prompt、RAG Guard、Agent 算法等。
- `tests/integration/`：认证、聊天、知识库、SSE、CORS、管理后台和 Agent API。

## 2. 前端

```cmd
cd frontend
npm run type-check
npm run test:unit -- --run
npm run lint
npm run build
```

## 3. 本次提交前静态审计

在清理后的源码上至少应满足：

- Python 源码可通过 `compileall`；
- Vue/TypeScript 类型检查通过；
- ESLint 无错误；
- 仓库无真实 `.env`；
- 仓库无 `.venv`、`node_modules`、`dist`、缓存、Chroma 运行数据、上传测试文件和 `.bak`。

## 4. 人工 RAG 验收用例

### 正常命中

上传退款政策，询问文档内明确存在的问题；预期回答引用真实来源。

### 空检索

询问知识库完全没有的信息；预期固定兜底且 sources 为空。

### 500 字边界

500 字可提交；501 字应在 API 参数/业务校验阶段被拒绝。

### 每日额度

达到配置上限后，下一次问题应在调用 LLM 前被拒绝。

### 来源伪造

模型若输出不存在的 `[来源N]`，最终显示/持久化结果不得保留虚构编号。

### 多知识库路由

创建退款库与物流库，分别配置路由关键词；问题应路由到对应知识库，最终来源不得串库。

### 多轮短追问召回

同一知识库中依次询问：

1. `星河智能耳机 X1 的保修期是多久？`
2. `售后客服电话是多少？`
3. `黑色型号内部产品代码是什么？`
4. `那30天内又有什么政策？`

预期 3、4 仍能命中同一文档中的产品代码和 30 天换新政策，不能因为上一轮问题语义不同而错误触发空检索。该用例用于回归 `Current-first + Context-fallback` 多轮检索策略。

### 关键规则

构造大量普通相似片段和一条高优先级“必须/不得”规则；预期关键规则进入 A 层并被 AnswerEvidenceGuard 强制覆盖。
